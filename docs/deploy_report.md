Key Architectural DecisionsSingle-Origin Reverse Proxy via CloudFront:The React (Vite) frontend communicates with the API using relative paths (/api/...) and credentials: 'same-origin'.CloudFront routes static asset requests (/*) to a private S3 bucket and proxies API requests (/api/* and /healthz) directly to the backend Lambda Function URL using AWS managed policies (CachingDisabled and AllViewerExceptHostHeader).Benefit: Eliminates Cross-Origin Resource Sharing (CORS) complexity, avoids hardcoding backend URLs into the frontend bundle at build time, and preserves HttpOnly / Secure session cookies (bz_session) under a single HTTPS domain.SPA Client-Side Routing Support:A lightweight CloudFront Function (bazhanka-spa-rewrite) intercepts viewer requests for extensionless routes (e.g., /wishlists/...) and rewrites them to /index.html, ensuring React Router handles deep links without 403/404 S3 errors.Zero-Code-Change Containerized Lambda (AWS Lambda Web Adapter):The Express 5 server (backend/src/index.js) is packaged in backend/Dockerfile.lambda alongside the AWS Lambda Web Adapter (v0.9.1).The adapter translates Lambda invocation events into standard HTTP requests on port 3000 and verifies readiness via /healthz, allowing the exact same Express application to run identically in local Docker Compose and AWS Lambda.Scale-to-Zero Relational Database (Aurora Serverless v2):PostgreSQL runs inside a private VPC subnet group with MinCapacity: 0 ACU and SecondsUntilAutoPause: 300.When idle for 5 minutes, compute pauses automatically (incurring zero compute charges) and resumes automatically (~10–15 seconds cold start) upon the next incoming database connection.Database schema migrations (migrate() in backend/src/db.js) are idempotent and execute automatically on container startup.3. Security & Configuration ManagementNetwork Isolation: The Aurora PostgreSQL cluster (publiclyAccessible: false) accepts TCP traffic on port 5432 only from FunctionSecurityGroup attached to the Lambda function. All database connections enforce SSL (DATABASE_SSL=true).Private Storage: Public access to bazhanka-frontend-283609055480 is completely blocked (BlockPublicAcls, BlockPublicPolicy, RestrictPublicBuckets). S3 bucket policy permits s3:GetObject exclusively to the CloudFront distribution ARN.Secret Handling: Sensitive credentials (AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_DB_PASSWORD, AWS_JWT_SECRET) are stored locally in a gitignored .env file and injected into CloudFormation parameters (NoEcho: true) at deployment time—never committed to version control.Immutable Image Pinning: make aws-deploy-backend resolves the exact SHA-256 image digest (repo@sha256:...) after pushing to ECR, guaranteeing deterministic deployments.5.
